# ScientificRadar Web — Public Content Model & Studio Adapter Contract (`v1.0.0`)

## 1. Architectural Separation (Stage A vs. Stage C)

- **Stage A (Current Standalone Website):** `ScientificRadar Web` consumes an isolated, strongly typed in-memory demonstration repository (`lib/content/repository.ts` backed by `lib/content/fixtures.ts`). It has zero runtime or build-time coupling to `ScientificRadar Studio`'s browser `IndexedDB`, CKEditor, or Tiptap packages.
- **Stage C (Versioned Snapshot Contract `v1.0.0`):** `lib/content/contract-v1.ts` defines `PUBLICATION_CONTRACT_VERSION = "1.0.0"` (`PublishedSnapshotRecordV1`), deterministic validator `validatePublicationSnapshotV1`, and adapters (`adaptSnapshotV1ToPublicArticle`, `adaptPublicArticleToSnapshotV1`). When authorized by the project owner, `InMemoryDemoContentRepository` can be replaced by a server-authenticated `PublishedContentRepository` reading immutable, validated `v1.0.0` snapshots.

## 2. Content Invariants Enforced in Code

1. **Draft & Non-Public Exclusion (`isPubliclyVisibleArticle` & `validatePublicationSnapshotV1`)**: Any record with `status` in `{"draft", "in_review", "scheduled", "archived", "withdrawn"}` is strictly filtered out from `listPublicArticles`, `getPublicArticle`, and `getRelatedArticles`. Requesting a draft or withdrawn slug returns HTTP 404 (`noindex, nofollow`).
2. **Single-H1 Semantic Hierarchy & Unified TOC Extraction**: The article route renders `<main id="main-content"><article>` with exactly one `<h1>` in `ArticleHeader`. Section headings inside `ArticleReader` use `<h2>` and `<h3>` exclusively. `sanitizeCanonicalBodyHtml` automatically demotes any accidental `<h1>` inside raw `bodyHtml` snapshots to `<h2>`, and `prepareCanonicalBodyHtml` / `resolveArticleHeadings` deterministically assign unique `id` attributes and extract `<h2>` headings so both `blocks` and `bodyHtml` articles render identical Desktop Left Rail and Mobile Disclosure (`ResponsiveArticleToc`) outlines.
3. **Citation & DOI Integrity**: Every inline citation renders `<a data-citation-source-id="..." id="cite-..." href="#ref-...">` linked to the corresponding `#ref-...` item in `CitationList` with a back-link anchor. Demonstration fixtures never fabricate synthetic DOIs (`doi` is `undefined` and `isIllustrativeDemo: true`). In `v1.0.0` validation, broken citation references or synthetic demo DOIs fail closed.
4. **Scientific Figures, Media Provenance & Tables**: Figures preserve explicit `width`, `height`, `alt`, `caption`, `credit`, `rightsVerified`, and `license`. `isSafePublishedMediaUrl` rejects ephemeral browser URLs (`blob:`, `data:`, `file:`, `javascript:`) and untrusted external origins. Wide figures (`layout: "wide"`) expand up to `--sr-figure-max` (`1100px`) on desktop while remaining 100% fluid within mobile viewports (`390px` and `320px`). Tables wrap in an independent `overflow-x-auto` container with `tabular-nums`.
5. **Controlled KaTeX Math Rendering**: Both `math` blocks and `bodyHtml` elements with `data-math-tex` render accessible KaTeX HTML + MathML (`output: "htmlAndMathml"`, `trust: false`) inside `role="math"` containers, falling back safely to escaped text if invalid or oversized TeX is encountered.
