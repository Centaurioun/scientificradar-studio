## 1. Executive Summary

**Verdict: a substantial, isolated editorial CMS prototype—not yet a verified or production-safe scientific publishing platform.** The main branch contains real implementation for the Next.js editorial dashboard, article catalog, Tiptap body editor, local IndexedDB model, revision snapshots, deterministic SEO/quality audit, pre-publish UI, time-zone conversion, and disconnected service settings. The README's “Working” statements describe author intent; absent executed build/browser evidence, they cannot certify functionality.

**Immediate risk is not a shortage of toolbar buttons.** The highest-impact concerns are incomplete HTML trust boundaries, fire-and-forget whole-snapshot writes, impermanent uploaded file URLs, schedule actions bypassing the review/role gate, and a pre-publish modal that evaluates an assumed role/state. Address these before enabling editable HTML source, mathematical nodes, live publishing or external integrations.

The v5 feature work has materially landed on main, whereas v6 remains predominantly a specification. **LaTeX/KaTeX is an explicit product requirement**, ranked P1 after the HTML safety and serialization foundations, not an optional nice-to-have. Distinguish “feature present in source” from “browser-verified”; no runtime verification was performed here.

### 5.1 P0 — Security, correct states and data safety

**SRS-SEC-001 — Regex sanitizer used before raw HTML render.** Evidence: **Confirmed by source code**. [lib/editorial-rules.ts#L156-L200](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/lib/editorial-rules.ts#L156-L200) strips a short list of tags/handlers/quoted schemes by regular expression, not an HTML parser + allowlist. [app/pages/[id]/preview/page.tsx#L60-L70](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/app/pages/[id]/preview/page.tsx#L60-L70) and [components/knowledge/knowledge-link-popover.tsx#L175-L290](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/components/knowledge/knowledge-link-popover.tsx#L175-L290) then use dangerouslySetInnerHTML. **Impact:** unsafe imported or malformed markup may reach DOM, and security is not provable by the existing single happy-path sanitizer test; exploitation not browser-proven. **P0.** Replace security boundary with a tested allowlist/DOM parser appropriate for SSR and client, strict URI/attribute/style validation, and enforce on paste, save, import, restore and rendering. Regression: malicious mixed-case/unquoted protocols, SVG/MathML/foreignObject, handler syntax, malformed nesting, encoded URLs; legitimate footnote/sup/sub/table/code/math preservation. **Never enable unrestricted source HTML.**

**SRS-SEC-002 — Imported backup bypasses content/schema validation.** Evidence: **Confirmed by source code**. [lib/studio-context.tsx#L1512-L1541](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/lib/studio-context.tsx#L1512-L1541) checks only that two top-level fields are arrays, then replaces state with untrusted JSON; imported HTML later reaches preview sinks. **Impact:** corrupted/malicious import, broken references, misleading audit/review state. **P0.** Versioned schema validation, sanitized article/page bodies, reference integrity, size limits, migration, dry-run/preview, confirmation and rollback; test adversarial imports and failed writes.

**SRS-DATA-001 — Non-editor state writes are fire-and-forget whole-snapshot operations.** Evidence: **Confirmed by source code**. [lib/studio-context.tsx#L256-L296](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/lib/studio-context.tsx#L256-L296) calls void persistState(next) inside a React state updater. Status, quick-fix, media, settings, calendar, imported backup flows use this path. **Impact:** optimistic success despite failed storage, out-of-order writes can replace newer state. **P0.** Serialize/revision-guard persistence; return awaited receipts for all significant mutations, avoid side effects in state updaters, report volatile state honestly. Reproduction/regression: two ordered and reordered writes, simulated storage failure, reload after media/review action, consistency across tabs.

**SRS-DATA-002 — Autosave and version check do not establish multi-operation atomicity.** Evidence: **Probable / requires reproduction**, supported by [lib/studio-context.tsx#L618-L665](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/lib/studio-context.tsx#L618-L665), [components/editor/article-workspace.tsx#L332-L368](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/components/editor/article-workspace.tsx#L332-L368), and stateRef updated in [lib/studio-context.tsx#L200-L209](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/lib/studio-context.tsx#L200-L209). Editor awaits one save, but version increments primarily for explicit snapshots; no atomic IndexedDB read-modify-write per article or cross-tab lock. **Impact:** race/stale draft overwrite and false clean state under overlapping writes. **P0.** Introduce per-draft monotonic edit sequence + single-writer queue; transactional compare-and-swap or conflict reconciliation; test delayed earlier save vs later edit and simultaneous tabs.

**SRS-MED-001 — Uploaded media persists only a blob URL, not the file.** Evidence: **Confirmed by source code**. [app/media/page.tsx#L62-L76](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/app/media/page.tsx#L62-L76) uses URL.createObjectURL(file) and records src; [lib/studio-context.tsx#L1404-L1450](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/lib/studio-context.tsx#L1404-L1450) persists that URL string. **Impact:** after document/browser session closes the file is unavailable although metadata survives; user may think asset was saved. **P0.** Store Blob bytes in a dedicated IndexedDB media object store, or explicitly make upload session-only and block durability claims until a real adapter exists; revoke URLs on cleanup. Regression: upload, save, reload/new session, preview, export/import handling, quota failure.

**SRS-PUB-001 — Calendar directly schedules with saveArticle, bypassing publishing policy.** Evidence: **Confirmed by source code**. [app/calendar/page.tsx#L67-L107](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/app/calendar/page.tsx#L67-L107) directly writes status scheduled regardless of review eligibility, apart from a published-state guard. Status authority only exists if caller opts to use [lib/studio-context.tsx#L849-L872](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/lib/studio-context.tsx#L849-L872). **Impact:** draft or wrong demo role can mark a publication slot without reviewer approval or pre-publish check; no live site currently affected. **P0.** Route calendar scheduling through one validated transition API with actual role, current state, audit and persisted receipt. Test each role × state × blocker/warning, failed save and DST.

**SRS-PUB-002 — Pre-publish dialog checks an imagined editor/approved context.** Evidence: **Confirmed by source code**. [components/audit/pre-publish-dialog.tsx#L25-L51](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/components/audit/pre-publish-dialog.tsx#L25-L51) passes only report to [lib/audit/publish-policy.ts#L25-L79](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/lib/audit/publish-policy.ts#L25-L79), which defaults currentStatus=approved, activeRole=editor, isDirty=false. **Impact:** modal may display “can publish” while actual status/role transition later refuses it; cannot be treated as reliable authority. **P0.** Require explicit actual article status, role, expected version and save state, then recheck atomically at commit. Test draft/reviewer/failed-save/warnings and direct callback bypass.

**SRS-DATA-003 — Return values and revision claims are optimistic for review/quick fix.** Evidence: **Confirmed by source code**. [lib/studio-context.tsx#L673-L809](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/lib/studio-context.tsx#L673-L809) returns an updated article or generated audit from synchronous updateState even though persistState is detached; [lib/studio-context.tsx#L849-L928](https://github.com/Centaurioun/scientificradar-studio/blob/6ba8028a1b26773992a4e19631446bded5595cc4/lib/studio-context.tsx#L849-L928) signals transition ok before durable write. **Impact:** “saved revision” can be false if IndexedDB fails. **P0.** Align all action receipts with durable commits. Regression: failure injection for quick fix, review transition, import and publish.

## 6. Focused Defect Diagnosis: Evidence → Mechanism → Test

1. **Media loss after reload:** upload file → object URL generated → only URL string saved → invalid when source document disappears → thumbnail missing. Reproduce by uploading local PNG and reopening the application, not by demo-generated SVG. Acceptance: bytes remain accessible or explicitly flagged ephemeral.
2. **Out-of-order persistence:** mutate state A → async root put(A); mutate B → async put(B); asynchronous order is uncontrolled → older snapshot may win. Instrument deterministic delays and verify persisted B, every error reported.
3. **Publishing bypass:** switch demo role to reviewer/author, select draft in calendar → direct saveArticle sets scheduled regardless of transition matrix. Confirm with status persisted after reload; ensure no direct state mutation can bypass policy.
4. **Audit stale false-positive:** article with linked source/media → runAndStoreArticleAudit uses complete fingerprint → SEO page compares article-only → stale indicator. Test unchanged report and after linked metadata edit.
5. **HTML trust:** import HTML with adversarial attributes via JSON backup → state accepts it → preview uses raw HTML injection sinks. Treat as *source-confirmed missing security validation*; exploitability requires controlled browser reproduction, not a claimed penetration-test result.

## 8. LaTeX / KaTeX Architecture (Explicit Planned Requirement)

**Recommendation:** preserve Tiptap v3, use the official open-source mathematics extension in the same compatible v3 family with KaTeX, after compatibility inspection against the *resolved* lockfile; see [Tiptap Mathematics documentation](https://tiptap.dev/docs/editor/extensions/nodes/mathematics) and [KaTeX security options](https://katex.org/docs/security). Avoid replacing Tiptap, building a LaTeX compiler, buying premium DOCX converters or introducing a second free-form HTML renderer.

- Define **atomic inline equation** and **block/display equation** ProseMirror nodes with an immutable node type, editable **LaTeX source** attribute, and explicit schema-approved serialization; example inline E = mc² and display E = hc/λ. Support user-friendly source delimiters such as \(…\) and \[…\] in imports without relying on auto-detection of ambiguous literal dollar signs.
- Provide Insert Equation / Edit LaTeX dialog, live safe KaTeX preview, error message for invalid TeX and keyboard editing, with no silent content replacement. Store raw TeX, **not rendered KaTeX HTML as canonical source**.
- Renderer: KaTeX configured with trust:false, bounded maxExpand/maxSize, throwOnError:false or handled error boundaries, output htmlAndMathml when practical; no arbitrary macros/URL loading or arbitrary raw HTML. Escape/display error text safely.
- Save/reload, article preview, sanitized HTML source, revisions, JSON export/import and reader preview must preserve raw LaTeX and node distinction. The existing regex-based article renderer will otherwise drop block math; replace it with a schema-aware renderer first.
- Support Greek letters, fractions, indices, units and scientific notation, semantic sup/sub for simple text, responsive horizontal scroll for wide display formulas, screen-reader math/MathML, and accessible source fallback.
- **No claim of universal DOCX equation import:** official Tiptap conversion docs explicitly note limited OMML import support ([reference](https://tiptap.dev/docs/conversion/content-types/structures-and-media/math-equations)). Paid import tooling is unjustified until measured user demand.

**Dependencies:** SRS-SEC-001 → SRS-HTML-002/renderer fidelity → SRS-MATH-001 → editable source SRS-HTML-001 integration acceptance. **Acceptance fixtures:** one inline quadratic, one multiline display fraction, invalid TeX, escaped less-than and ampersand, Greek/indices, undo/redo, reload, revision restore, export/import, mobile, HTML-source transition, unsafe KaTeX commands refused.

## 9. HTML Source Mode and Content Security Decision

**Decision:** read-only body HTML inspection first; editable body source *only after* parsed/sanitized allowlist, schema-aware parse and tested roundtrips. The editor remains WYSIWYG-first, and only the ARTICLE BODY is edited in source—not page shell, SEO inspector, script tags or server templates. Maintain a separate uncommitted source draft with Apply / Discard and diff; if unsupported markup would be dropped, block Apply and explain why. Run the same validation at import/paste/revision/save/preview—not just on button click. Preserve heading invariant and durable save receipts.

**Alternatives rejected:** unrestricted source HTML (XSS), regex-only sanitizer (fragile), a second general-purpose CMS/editor (migration risk), storing rendered math markup instead of raw TeX (irreversible), one-click destructive HTML cleanup (scientific data loss).

## 10. SEO, Publishing and Scientific Integrity

**What exists:** one runArticleAudit evaluator used in list/detail/editor and quick-fix proposals; explicit pass/warning/error/unverified; noindex for isolated prototype; DOI pattern validation; source/media audit, role matrix, review queue, manual revision and pre-publish dialog.

**What does not follow:** this is not Google index readiness; content descriptions/titles are editorial heuristics, not Google hard cutoffs; valid DOI syntax does not prove registered or relevant literature; human verification flag does not establish claim-to-source correspondence; an audit marked “passed” cannot substitute for a reviewer. Fix stale fingerprint inputs and route ALL publication/scheduling mutations through the same authoritative pre-publish checks. Include review provenance, warning override justification and correction logs before live publication.

## 11. Persistence, Security, Accessibility and Performance

P0 reliability requires whole-store serialization or normalized transactional storage, explicit persistence acknowledgments and schema/version validation. Distinguish memory fallback from durable IndexedDB; recover when storage quota or permissions fail. Large seeded context and full-snapshot writes may cause excessive rerenders and storage cost, but no profiling has been executed. Validate aria-pressed/disabled states, toolbar overflow, dialog focus traps and mobile math/tables before UI acceptance. Check CSP and remote asset policy independently before any production-facing HTML.

## 16. Six-Cycle Iterative Refinement — Independent Decision Log

### Cycle 1 — Requirements and intent
**Initial:** Treat Master, v5 and v6 as implementation checklist; earlier README marks major P0 features “Working”. **Challenge:** A document or AI completion report is not a passing test; v5 requirements may already have code. **Source comparison:** v5 date formatter, DST parser, runArticleAudit, dirty-state editor and pre-publish dialog already exist. **Revision:** Reclassify these as source-present but runtime-unverified/partially implemented, rather than “missing”; classify v6 source/edit, tables, math as actual gaps. **Removed/merged:** Removed duplicate “build SEO engine” proposal; retained targeted fingerprint/gate corrections. **Outcome:** Prevents redundant rewrites while preserving acceptance gates.

### Cycle 2 — Architecture and feasibility
**Initial:** Expand framework or replace Tiptap for scientific formatting; introduce production DB to fix writes. **Challenge:** Existing data models and 3.32.x Tiptap stack already support richer nodes, whereas storage failure comes from non-awaited snapshot puts and mixed mutation APIs. **Revision:** Retain Tiptap, choose official open-source mathematics nodes and durable serialized local writes first, with normalized/server storage a later separate decision. **Removed/merged:** Dropped editor replacement, paid DOCX conversion, premature multi-service backend. **Outcome:** Lower implementation risk and exact file ownership for the next developer.

### Cycle 3 — UX and editorial efficiency
**Initial:** Add a toolbar button for every v6 requirement. **Challenge:** More controls worsen long-form writing on tablet/mobile; doubled heading glyph+label and single-line title already consume space. **Revision:** One accessible style selector, primary writing controls, contextual More/Insert; wrap long title; conditional figure button must actually be wired. **Removed/merged:** Merged H2/H3 appearance and responsive toolbar as one UX task; deferred custom fonts, floating bubble overload and exotic table editing. **Outcome:** Fewer high-frequency clicks without a Word-style ribbon.

### Cycle 4 — Scientific integrity, security and data safety
**Initial:** Deliver editable HTML and equations immediately, since scientists need both. **Challenge:** Regex sanitizer feeds dangerouslySetInnerHTML, the preview renderer recognizes only some blocks, object URLs are non-durable, and import accepts untrusted HTML. Adding rich markup now risks XSS/silent data loss. **Revision:** Make sanitizer, schema, renderer and import validation P0, make equation persistence a P1 requirement dependent on safe serialization; deliver read-only source before editable. **Removed/merged:** Rejected free-form HTML execution; collapsed generic “HTML problems” into separate security and roundtrip issues; added media durability and human citation provenance. **Outcome:** Source fidelity and scientific evidence remain first-class quality constraints.

### Cycle 5 — Priority and dependency analysis
**Initial:** Prioritize visible editor additions ahead of plumbing because they are user-requested. **Challenge:** Publish can be scheduled via a bypass, modal gate assumes approved/editor, and storage writes can acknowledge success before durability. **Revision:** Promote publish state, storage and file persistence to P0; place core editor UX and mandatory math at P1; hold Cloudflare, Google and live Codex at P2 until production auth and consent. **Removed/merged:** Removed independent second publishing validation per screen; plan one domain policy enforced everywhere. **Outcome:** Independent acceptance tests and an achievable Next 10 rather than “everything urgent”.

### Cycle 6 — Independent verification and scope stress-test
**Initial:** Label all observable source controls “verified” and attribute draft PR #1 hydration fixes to main. **Challenge:** No tests, builds or browser were run; PR #1 diverges 6 ahead/3 behind and its UTC-only solution predates main's locale/DST code; claiming a live XSS exploit would overstate evidence. **Revision:** Separate source-confirmed flaws, probable races, specification gaps, external unverified services. Do not merge PR #1 or blindly copy its patch. **Removed/merged:** Removed runtime success language and duplicate backlog items; kept explicit browser and persisted-data checks. **Outcome:** Final audit is falsifiable, traceable and bounded to actual evidence.

## 17. Proposed Development Phases

**Phase 0 — Acceptance and safeguards:** establish CI/e2e scaffolding, HTML import/paste/render trust boundary, durable media, serialized writes, actual publishing policy and recovery. No live publishing.

**Phase 1 — Editorial correctness & core usability:** extension deduplication, title wrapping, toolbar grouping, figure insertion, accurate audit fingerprints, paste/reader parity, basic semantics, find/replace, citation references and precise reviewer records.

**Phase 2 — Scientific mathematics and safe source authoring:** verified Tiptap math+KaTeX inline/block, math source dialog, cross-mode persistence; read-only source view then gated editable body-only source once round-trip evidence exists. This remains P1 product priority despite its dependency on Phase 0/1 safety work.

**Phase 3 — Production foundations (separate authorization):** server identity/RBAC, per-record persistence, publish scheduler, storage/transform provider with rights/quotas, audit integrity and public SEO data contract.

**Phase 4 — Optional external reach:** Codex sign-in/provider, Search Console/GA4/GTM/AdSense as individually approved integrations; optional structured citation retrieval and performance analytics. Don't develop these just because settings cards exist.

## 18. Open Decisions Requiring Owner/Product Review

1. Is the first public release single-editor or multi-role production? Determines whether a server backend is required before public deployment.
2. Should scientific articles retain verbatim author LaTeX source in HTML nodes, and which delimiters are accepted on paste? Default proposed: raw node latex attribute, explicit source UI.
3. Should document/Word paste reject unsupported tables/equations with an alert or preserve a lossless attachment/source draft? Default: avoid silent dropping, show warning.
4. Which scientific citation style(s) and per-claim verification provenance are essential first? Default: one stable source-ID system, formatting style later.
5. What is the legitimate licensing model for uploaded illustrations? Never automatically assert CC BY rights to unknown files.
6. Is R2 required before launch? Current evidence suggests local Blob storage first, provider integration only with a real release need.
7. Which workflows must be accessible at 390px in one tap? Validate in browser rather than redesign every screen.
8. Are existing source/import snapshots shared between accounts? If yes, local-only concurrency must be replaced by server policy.
