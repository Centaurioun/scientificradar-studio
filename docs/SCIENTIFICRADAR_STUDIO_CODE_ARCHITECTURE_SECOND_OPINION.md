# ScientificRadar Studio — Independent Code Architecture Second Opinion

> **Scope:** Independent, skeptical, documentation-only review of the actual P0 isolated prototype, against the Master, v5 and v6 requirements. **Evidence cutoff:** 2026-11-01. **Audited main:** [c099ae0a78bf69a4b5f58785dcf2c3512e9b270d](https://github.com/Centaurioun/scientificradar-studio/commit/c099ae0a78bf69a4b5f58785dcf2c3512e9b270d). **Status:** SOURCE-ONLY REVIEW; NOT a runtime-security certification, successful build, browser acceptance or production-readiness sign-off.

## 1. Executive conclusion

**Assessment: structurally useful isolated scientific CMS prototype; NOT a reliable durable editorial/publishing system.** Next.js App Router, React 19, Tiptap 3, a typed editorial model, meaningful local SEO checks, explicit offline-provider honesty, revision snapshots and timezone helpers are real source-level capabilities. Retain the stack. The highest-risk weaknesses are at *cross-module boundaries*, rather than the absence of a fashionable architecture: whole-snapshot writes with unacknowledged mutations; weak HTML and backup trust boundaries; multiple status mutation paths without a uniform publish gate; divergent Tiptap JSON/HTML; and ephemeral uploaded image URLs. Controlled exploit, browser loss, hydration failure or benchmark results have **not** been demonstrated.

The first audit's main engineering diagnosis is substantially independently confirmed. Its 49 entries should not be multiplied by creating duplicate tickets. **Two distinct omitted cases** warrant new conditional tasks: SR2-12 / SRS-CODE-001 (empty snapshot reseeding) and SR2-13 / SRS-CODE-002 (nonexistent sample figure asset). Several earlier P0 labels are *acceptance priorities*, not evidence of currently reproduced severity.

**Delivery discipline:** this report adds no implementation, package, configuration or backlog edits; the baseline SHA throughout is the main commit above. Positive and negative findings are equally recorded.

## 5. Architecture assessment and bounded recommendation

The correct architectural unit is presently **the in-browser editable record plus related sources/media/audit**, but the implementation persists it as one root snapshot shared by every module. This creates a coordination boundary problem: the editor knows when its own IDB write returned, while calendar, review, taxonomy, pages and backup import share a synchronous context API and cannot prove durability. A minimal serialized mutation repository is appropriate before considering per-record IDB transactions; no evidence supports PostgreSQL, microservices or an editor migration in Gate P0.

The domain model includes appropriate explicit status, locale, revisions, source review and figure metadata, but TypeScript interfaces do not enforce imported runtime shapes. Tiptap HTML and JSON cannot both be independently canonical. Read-only source evidence favors preserving Tiptap v3 while defining one canonical tree and a controlled render/export projection.

The existing central SEO engine is worth preserving. Fingerprint inputs, not rule-engine proliferation, need correction. App Router is a reasonable presentation shell; do not mistake a demo role selector for a server security feature.

## 10. Scientific editor, structured citations and LaTeX/KaTeX design

**Current:** Tiptap v3 family in [package.json:17–23](https://github.com/Centaurioun/scientificradar-studio/blob/c099ae0a78bf69a4b5f58785dcf2c3512e9b270d/package.json#L17-L23); StarterKit H2/H3, paste sanitization, simple inline formatting and undo/redo. Semantic table, sup/sub, inline/block LaTeX and body-only editable HTML Source are absent. Source records exist, but body citations are not structurally tied to ScientificSource.id. **Do not claim installed Tiptap Mathematics or KaTeX support.**

**Architectural choice:** retain Tiptap 3; canonical *versioned Tiptap JSON document with schema validation*; generate HTML from supported schema at the trusted rendering boundary and preserve raw TeX verbatim in dedicated immutable-position nodes: mathInline/MathInline and mathBlock/MathBlock (actual extension names/version must be verified), attributes tex, displayMode, and optional human-edit metadata. Render TeX with KaTeX under trust disabled and restricted macros; store raw source independent from rendered HTML and provide accessible source or MathML where supported. Erroring TeX remains visible/editable without losing raw text; never run arbitrary HTML/JS from formula contents.

**Compatibility/availability evidence:** Tiptap's published Mathematics extension documentation describes inline and block support and a KaTeX dependency, but the extension is **not in this repo's manifest** and source-only review cannot prove its exact API/runtime compatibility at 3.32.2. Official documentation: https://tiptap.dev/docs/editor/extensions/nodes/mathematics ; StarterKit extension composition: https://tiptap.dev/docs/editor/extensions/functionality/starterkit ; Mathematics migration details: https://tiptap.dev/docs/resources/changelog/extension-mathematics . Check package version, licensing and the actual imported node schema before a future implementation. Do not assume premium conversion is required.

**Safe future order (requirements, not implementation):** (1) parser sanitizer/import contract and regression harness; (2) canonical body migration with reversible JSON+HTML fixtures; (3) deduplicate installed extensions; (4) semantic sup/sub, alignment, tables with header cells/captions and language-aware marks; (5) stable source-ID citation marks and immutable provenance / human sign-off; (6) dedicated inline/block TeX and KaTeX preview; (7) version/reload/reader/export preservation; (8) read-only body source inspector, then editable body-only Source with explicit Apply/Discard and unsupported-content diff. Preserve the whole original manuscript when unsupported markup is encountered; never silently drop scientific values.

**Acceptance fixtures:** inline H₂O/CO₂, E=mc² superscript, a subscripted sample ID, inline quadratic, display fraction, malformed TeX, 3×3 table with decimal precision and caption, bilingual Turkish/English headings, Figure 1 caption/license, source-ID citation, multi-level list, HTML source apply/discard, undo/revision restore and JSON/HTML export. Require DOM and content equality assertions with meaningful tolerances, not screenshots alone. No automated tool may infer that a citation supports a factual claim.
